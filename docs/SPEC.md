## 1. 專案背景

- 專案名稱：Teaching Studio｜通用教學簡報工作台
- 使用對象：教師、講師、簡報者
- 核心定位：**教材播放載體＋即時教學輔助工具**；不是簡報編輯器、班級管理系統或 LMS
- 使用設備／環境：Windows Chrome、Edge；iPad Safari；教室 16:9 投影
- 架構：純前端，部署於 GitHub Pages；第一版不使用 Supabase、不建後端

## 3. 完整流程與例外情況

- 進入網站：未載入教材時顯示簡潔的新增教材引導（§5.1 C）。
- 主要流程：課前準備加入教材與設定工具 → 開始展示 → 課堂中翻頁並使用工具 → 結束展示（§5.2、§5.3）。
- 重新整理／關閉：工作階段資料可能清除，應提示；不宣稱可可靠攔截（§6.4）。
- 外部播放器失敗、網路中斷：不得影響本機 PDF 與課堂工具（§19 情境 G）。

## 4. 不在本次範圍（第一版）

原生 PPT／PPTX 解析、PowerPoint 自動轉檔、簡報編輯、帳號登入、班級管理、雲端教材儲存、跨裝置同步、學生端即時互動、遠端簡報控制、講者備忘稿／雙螢幕講者模式、在第三方簡報上繪圖或批註（§4.2）。**未經使用者確認不得擴充。**

## 5. 不能更動的條件

- 已確認產品決策（§3）不再提出替代方案要求使用者選擇。
- 本機 PDF、學生名單、QR Code 網址不自動上傳、不預設永久保存（§6.4、§8.4、§14.3、§17.1）。
- 第三方 iframe：不存取 DOM、不假設可讀頁碼、不使用模擬成功的控制按鈕（§7.2）。
- 不透過代理服務繞過來源網站存取限制（§9.3）；不繞過 Canva 存取控制（§10.2）。
- LayoutState 變更不得重設 PlayerState／ToolState；工具列、浮層、展示模式切換不得造成播放器重新建立（§16）。
- 不得以 CSS 最大化宣稱已進入瀏覽器原生全螢幕（§15.2）。
