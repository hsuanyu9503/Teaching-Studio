## 1. 專案背景

本專案旨在建立一個供教師、講師及簡報者使用的通用教學簡報工作台，暫定名稱為 Teaching Studio。

核心定位：

**教材播放載體＋即時教學輔助工具。**

使用者可以在同一個網站內載入 PDF、PowerPoint 線上簡報及 Canva 簡報，將多份教材排列成單次課程的播放清單，並於教學過程中隨時使用計時器、抽籤器與 QR Code 產生器。

本專案不是簡報編輯器、班級管理系統或學習管理平台。

設計核心為：

- 教材是主要展示內容。
- 工具應隨時可用，但不干擾教材。
- 課前準備與課堂展示應有一致且流暢的操作體驗。
- 不因切換工具或調整版面而中斷教材播放。
- 優先確保穩定性、易用性與教學現場的可靠性。

## 3. 已確認的產品決策

以下項目為正式確認的需求，不需重新提出替代方案要求使用者選擇。

### 3.1 教材來源

支援：

1. 本機 PDF 檔案。
2. PowerPoint 網頁版／OneDrive 官方嵌入。
3. Canva 官方嵌入。

PowerPoint 採用 A＋B 方案：

- 方案 A：使用者先將 PowerPoint 匯出成 PDF，再透過 PDF 播放器展示。
- 方案 B：透過 PowerPoint 網頁版或 OneDrive 官方提供的嵌入方式播放。

第一版不實作本機 PPT 或 PPTX 原生解析、轉檔服務或完整動畫還原引擎。

### 3.2 教材管理

採用單次課程的多份教材清單。

允許混合加入 PDF、PowerPoint 及 Canva 教材。

第一版不需要帳號、跨裝置同步、雲端儲存或永久課程管理。

### 3.3 工具列

工具列必須支援：

- 收合模式。
- 展開並縮放教材模式。
- 浮層展示模式。

另須支援可拖曳的迷你計時器，以及大型工具展示視窗。

### 3.4 系統架構

採純前端架構為第一版開發基礎。

建議部署於 GitHub Pages。

第一版不使用 Supabase，不建置後端服務。

## 5. 工作台介面設計

### 5.1 整體結構

工作台包含：

A. 頂部控制列：

- 專案名稱。
- 新增教材。
- 教材管理。
- 開始展示／結束展示。
- 全螢幕操作。
- 必要的系統設定。

B. 左側教材清單：

- 教材名稱。
- 來源類型。
- 教材順序。
- 目前播放標示。
- 新增、重新命名、排序及移除。

C. 中央教材播放區：

- 根據教材來源呈現對應播放器。
- 保留教材原始長寬比例。
- 避免裁切、變形及不必要的捲軸。
- 在未載入教材時呈現簡潔的新增教材引導。

D. 右側工具抽屜：

- 計時器。
- 抽籤／選號器。
- QR Code 產生器。
- 工具展示模式切換。

E. 底部播放控制列：

- 依播放器能力提供上一頁、下一頁、頁碼跳轉、縮放等控制。
- 提供必要的教材切換操作。
- 不顯示無法實際運作的控制項。

### 5.2 課前準備模式

主要用於：

- 加入多份教材。
- 安排教材順序。
- 預覽教材。
- 設定計時器預設值。
- 設定抽籤範圍、名單及排除項目。
- 準備 QR Code 網址。

教師應能於正式展示前完成上述準備。

### 5.3 課堂展示模式

主要目標為最大化教材顯示。

需求：

- 隱藏非必要的編輯及管理控制項。
- 教材清單預設收合。
- 課堂工具列預設收合。
- 保留可操作的側邊拉柄。
- 播放控制可適度自動隱藏。
- 觸控裝置不可依賴 hover 才能顯示控制項。
- 教師可隨時返回準備模式。
- 兩種模式切換時不得重新初始化教材或工具狀態。

### 5.4 視覺方向

採簡潔、低干擾、專業的教學工作台風格。

建議：

- 深色或中性色工作台外框。
- 教材保留原有色彩。
- 清楚的文字層級。
- 一致的圖示與按鈕樣式。
- 適度留白。
- 適合觸控操作的按鈕尺寸。
- 大型展示內容適合教室後方學生閱讀。

視覺介面不得搶奪教材的注意力。

## 6. 教材管理模組

### 6.1 教材清單

使用者可以新增多份不同來源的教材。

每份教材應具有獨立識別 ID，不得以名稱作為唯一識別。

建議資料欄位：

- id
- title
- sourceType
- sourceReference
- order
- playbackState
- loadingStatus
- errorState

欄位應依各來源實際能力採用適當的 TypeScript 型別，不要求將所有資料強制放入相同格式。

### 6.2 操作需求

- 新增教材。
- 修改教材顯示名稱。
- 拖曳排序。
- 提供非拖曳的排序替代操作。
- 選擇目前播放教材。
- 移除指定教材。
- 清空本次課程教材。
- 標示載入中及載入失敗狀態。
- 移除失敗教材後不影響其他教材。

### 6.3 播放狀態

本機 PDF 必須保留各自的目前頁碼。

例如：

PDF A 播放至第 12 頁，切換至 PDF B，再返回 PDF A 時，應回到第 12 頁。

第三方 iframe 的頁碼、縮放及原生播放進度只能依官方支援能力處理。

應盡可能避免不必要的 iframe 重建。

若實際上無法取得或恢復第三方播放器進度，必須清楚區分此限制，不得宣稱已完整保留。

### 6.4 工作階段生命週期

第一版教材清單及工具狀態以目前瀏覽器工作階段為主。

預設不將本機教材、學生名單及 QR Code 網址寫入永久儲存。

重新整理或關閉網頁後，工作階段資料可能清除，應提供適當提示。

若教師已載入教材或正在計時，可評估在瀏覽器支援的情況下提供離開頁面的提醒。

不得宣稱所有瀏覽器均能可靠攔截關閉或重新整理行為。

## 7. 教材播放器架構

### 7.1 模組化播放器

請建立共用播放器介面及來源對應的 Adapter。

概念結構：

- PlayerManager
- PDFPlayerAdapter
- PowerPointEmbedAdapter
- CanvaEmbedAdapter

實際命名及檔案位置可依專案架構調整。

播放器共用介面應能描述：

- 載入及卸載生命週期。
- 載入狀態。
- 錯誤狀態。
- 目前播放來源。
- 播放控制能力。
- 資源釋放方式。

### 7.2 播放器能力管理

每種播放器應宣告實際支援的能力，例如：

- canNavigatePages
- canReadCurrentPage
- canReadTotalPages
- canZoom
- canRestoreProgress
- hasNativeControls

工作台應依能力顯示控制項。

不得假設所有播放器都能使用相同的翻頁、縮放及頁碼操作。

對於第三方跨網域 iframe：

- 不得嘗試未經授權直接存取 iframe DOM。
- 不得假設父頁面可以讀取目前投影片頁碼。
- 不得使用模擬成功的控制按鈕。
- 若使用 postMessage，須有官方支援依據，並驗證 origin、source 及訊息格式。
- 未經文件證實的 API 不應列為正式功能。

## 8. PDF 播放器

使用 PDF.js 建立自訂播放介面。

### 8.1 核心功能

- 選擇本機 PDF。
- 拖放 PDF 檔案。
- 單頁簡報模式。
- 上一頁、下一頁。
- 輸入頁碼跳轉。
- 顯示目前頁碼與總頁數。
- 自動適應容器大小。
- 保留原始長寬比例。
- 手動縮放。
- 回到適應畫面。
- 鍵盤方向鍵及空白鍵翻頁。
- 連續閱讀模式。
- 切換教材後恢復原頁碼。

### 8.2 效能需求

- 避免一次渲染所有 PDF 頁面。
- 評估相鄰頁預先渲染。
- 大型 PDF 應有適當載入提示。
- 連續閱讀模式應採合理的延遲渲染或虛擬化策略。
- 快速翻頁時避免過期的非同步渲染結果覆蓋最新頁面。
- 側欄展開、視窗縮放及裝置旋轉時應正確更新渲染尺寸。
- 釋放不再使用的 Canvas、PDF Document、渲染任務及 Object URL。
- 避免長時間切換教材導致記憶體持續成長。

### 8.3 錯誤處理

處理：

- 不支援的檔案格式。
- 損壞的 PDF。
- 密碼保護的 PDF。
- 渲染失敗。
- 檔案過大或資源不足。
- PDF.js worker 載入失敗。

若提供密碼輸入，密碼僅供當次本機開啟文件使用，不應永久保存。

### 8.4 隱私

本機 PDF 必須在瀏覽器端解析及渲染。

不得自動上傳至任何遠端伺服器、外部轉檔服務或分析服務。

## 9. PowerPoint 播放器

正式採用 PDF 替代及官方線上嵌入兩種方式。

### 9.1 PDF 替代

提供清楚的操作指引，說明如何將 PowerPoint 匯出成 PDF 並加入教材清單。

須提醒：

PDF 無法保留原始 PowerPoint 的動畫、轉場及互動影音能力。

本機 PPT／PPTX 檔案不得被錯誤識別為已支援的播放器格式。

### 9.2 官方線上嵌入

使用者可提供 PowerPoint 網頁版／OneDrive 官方支援的嵌入連結或嵌入程式碼。

系統應：

- 驗證來源網址。
- 辨識實際支援的官方嵌入格式。
- 安全擷取 iframe src。
- 由系統自行建立 iframe。
- 保留官方播放器可用的原生控制項。
- 提供重新載入及在原始頁面開啟的替代操作。

### 9.3 限制與錯誤處理

應清楚說明：

- 線上播放器需要網路。
- 分享權限與組織政策可能限制嵌入。
- 一般分享連結不保證可以直接嵌入。
- 第三方播放器動畫、轉場及影音支援程度需實際驗證。
- 跨網域限制可能使工作台無法自行翻頁或取得頁碼。
- 不得透過代理服務繞過來源網站的存取限制。

iframe load 事件不代表教材已成功且可操作地顯示。

應區分 iframe 容器已載入、播放器功能已驗證及實際內容無法判斷等狀態。

## 10. Canva 播放器

### 10.1 核心功能

- 支援 Canva 官方嵌入連結。
- 支援從合法嵌入程式碼擷取來源網址。
- 保留 Canva 原生簡報展示功能。
- 加入教材清單。
- 提供重新載入及開啟原始設計的替代操作。

### 10.2 安全與權限

- 不直接執行貼入的 HTML 或 JavaScript。
- 驗證官方來源網域及 URL 格式。
- 由系統建立受控的 iframe。
- 提醒使用者留意教材分享及公開權限。
- 若教材含有學生姓名、照片等敏感資訊，應避免為了嵌入而任意公開。
- 不繞過 Canva 存取控制。

### 10.3 相容性

若 Canva 原生播放器進入獨立全螢幕，可能影響工作台工具顯示。

應優先使用整個工作台的展示模式，並實際驗證 Canva 在該模式下的可用性。

不得宣稱所有 Canva 設計、動畫、影音及互動效果均可完整支援。

## 11. 側邊工具抽屜

### 11.1 收合模式

- 工具列隱藏。
- 只保留小型側邊拉柄。
- 教材使用最大可用展示空間。
- 收合後工具狀態持續保留。

### 11.2 並排縮放模式

- 工具列展開於教材右側。
- 教材使用剩餘空間。
- 教材等比例縮放，不裁切、不變形。
- PDF 應依新容器尺寸重新計算適合的渲染比例。
- 第三方 iframe 應調整容器大小，不因調整尺寸重新建立。

### 11.3 浮層模式

- 工具顯示於教材上方。
- 原教材展示區大小不變。
- 可關閉浮層並立即回到教材。
- 浮層應有清楚的關閉控制。
- 避免未顯示的浮層攔截教材點擊事件。

### 11.4 迷你浮窗

第一版用於計時器。

需求：

- 可拖曳。
- 支援滑鼠及觸控。
- 限制於目前可視區域。
- 視窗縮放及裝置旋轉時重新校正位置。
- 工具列收合後仍可顯示。
- 提供放大與關閉顯示功能。
- 關閉浮窗不等同停止計時。

### 11.5 大型展示

支援：

- 大型倒數計時。
- 大型抽籤結果。
- 大型 QR Code。

大型展示需：

- 適合教室投影。
- 保留原教材播放狀態。
- 避免重新掛載播放器。
- 可使用明確的關閉按鈕。
- 支援適當的 Escape 關閉行為。
- 關閉後恢復原先教材及操作焦點。

## 12. 計時器模組

### 12.1 功能

- 倒數計時。
- 正向計時。
- 1、3、5、10、15、20、30 分鐘快捷設定。
- 自訂分鐘及秒數。
- 開始。
- 暫停。
- 繼續。
- 重設。
- 可設定結束音效。
- 可設定靜音。
- 結束視覺提醒。
- 迷你浮窗。
- 大型計時展示。

### 12.2 狀態管理

計時器狀態至少包含：

- idle
- running
- paused
- completed

計時邏輯應依實際時間戳記或等效的時間基準計算。

不得單純依 setInterval 的執行次數累積時間。

須處理：

- 瀏覽器背景分頁節流。
- 分頁重新顯示。
- 暫停及繼續。
- 重複點擊開始。
- 多個計時顯示介面共用同一計時狀態。
- 工具列收合及展開。
- 教材切換。
- 展示模式切換。

所有計時顯示介面必須反映同一個計時狀態，不得各自建立獨立計時器。

### 12.3 音效限制

應考慮瀏覽器自動播放政策。

可於使用者主動操作時初始化音效播放能力。

不得保證裝置休眠或瀏覽器完全停止執行時仍能準時播放聲音。

恢復執行後應重新計算並呈現正確計時結果。

## 13. 抽籤／選號器

### 13.1 數字模式

- 設定起始號碼。
- 設定結束號碼。
- 驗證數字範圍。
- 排除指定號碼。
- 允許重複抽取。
- 不重複抽取。
- 顯示剩餘可抽取數量。

### 13.2 名單模式

- 貼上或輸入自訂名單。
- 支援逐行輸入。
- 移除空白項目。
- 適當處理重複名稱。
- 支援排除指定成員。
- 抽籤紀錄應能區分同名但不同的名單項目。

### 13.3 共用功能

- 抽取單一結果。
- 顯示抽籤結果。
- 顯示抽籤歷史。
- 重設已抽取項目。
- 大型結果展示。
- 可開啟或關閉動畫。
- 可用候選項目抽完後明確提示。
- 設定變更時應避免產生不一致的候選池。

抽籤動畫僅為視覺呈現，不得影響抽取機率。

應避免快速連續點擊造成重複執行或結果錯亂。

所有合法候選項目均應具有公平的抽取機會。

## 14. QR Code 產生器

### 14.1 功能

- 貼上網址。
- 自動產生 QR Code。
- 驗證網址格式。
- 網址變更時自動更新。
- 複製原始網址。
- 下載 QR Code PNG。
- 大型投影展示。
- 清空輸入及結果。

### 14.2 URL 處理

第一版以 HTTP／HTTPS 網址為主要支援範圍。

可評估對未輸入協定但具有明確網域格式的網址補上 HTTPS，並清楚顯示實際編碼的網址。

不得將 javascript:、data: 等不適合作為一般網頁連結的內容當成合法網址。

網址無效時應清除或標示舊的 QR Code，避免教師誤以為舊 QR Code 仍對應目前輸入。

### 14.3 安全與隱私

QR Code 須在瀏覽器本機產生。

不得使用會將輸入網址傳送給外部服務的 QR Code API。

不應為了產生 QR Code 而自動連線至使用者輸入的網址。

### 14.4 展示品質

- 維持足夠黑白對比。
- 保留標準留白區。
- 避免被其他圖案或文字遮擋。
- 長網址應保持足夠解析度。
- 大型展示須以實際手機掃描驗證。
- 匯出的 PNG 必須可正常掃描並指向正確網址。

## 15. 全螢幕與鍵盤操作

### 15.1 全螢幕

應優先以整個工作台作為全螢幕容器，而非僅對教材 Canvas 或第三方 iframe 進行全螢幕。

全螢幕模式中應保留：

- 教材切換。
- 工具列拉柄。
- 計時器浮窗。
- 大型工具展示。
- 必要的退出控制。

應處理 fullscreenchange、全螢幕要求失敗及使用者從瀏覽器原生操作退出全螢幕等情況。

### 15.2 替代展示模式

若瀏覽器或裝置不支援完整 Fullscreen API，應提供工作台內部的最大化展示模式。

此模式仍需保留工具操作及教材播放能力。

特別驗證 iPad Safari 的實際操作。

不得將 CSS 最大化模式描述成已成功進入瀏覽器原生全螢幕。

### 15.3 鍵盤控制

PDF 模式至少支援：

- 左方向鍵：上一頁。
- 右方向鍵：下一頁。
- 空白鍵：下一頁。
- Escape：依目前狀態關閉工具浮層或退出展示。

須避免：

- 使用者正在輸入文字時觸發翻頁。
- 按下工具按鈕時重複觸發快捷鍵。
- 在可編輯欄位或對話視窗中攔截必要鍵盤操作。
- 強制攔截第三方 iframe 的原生鍵盤事件。

應清楚定義工具浮層、工作台展示模式及瀏覽器原生全螢幕的 Escape 操作優先順序，並保留瀏覽器的原生退出能力。

## 16. 建議技術架構

優先評估：

- React。
- TypeScript。
- Vite。
- PDF.js。
- 本機 JavaScript QR Code 函式庫。
- React Context 或其他輕量且適當的狀態管理方案。
- GitHub Pages。

實際版本選擇須依相容性、授權、維護狀態及 Starter Kit 現行規範確認。

建議模組結構：

- app：應用程式入口及工作台。
- features/materials：教材清單及教材狀態。
- features/players：共用播放器及來源 Adapter。
- features/timer：計時邏輯與顯示元件。
- features/picker：抽籤邏輯與候選池。
- features/qrcode：網址驗證與 QR Code 生成。
- features/presentation：展示及全螢幕管理。
- components：共用介面元件。
- hooks：共用操作邏輯。
- utils：共用工具函式。
- tests：單元、整合及端對端測試。

以上為建議結構，不應為了符合目錄名稱而增加不必要的抽象或複雜度。

### 16.1 狀態分離原則

至少區分：

1. MaterialState：教材清單及目前播放項目。
2. PlayerState：各教材播放狀態。
3. ToolState：各課堂工具的操作狀態。
4. PresentationState：準備模式、展示模式與全螢幕狀態。
5. LayoutState：左右側欄、浮窗及大型展示狀態。

調整 LayoutState 不應造成 PlayerState 或 ToolState 重設。

切換 PlayerState 不應中斷正在執行的計時器。

### 16.2 播放器生命週期

請特別確認 React 元件 key、條件渲染及路由切換是否會造成播放器重新掛載。

工具列收合、浮層開關及展示模式切換，不得成為播放器重新建立的條件。

切換教材時，若需要保留第三方 iframe，應在進度保留、背景影音及記憶體資源之間採取合理策略。

不得讓未啟用教材持續意外播放聲音。

## 17. 安全與部署

### 17.1 安全

- 驗證所有外部嵌入網址。
- 使用明確且可維護的官方網域白名單。
- 不使用任意 URL 或字串包含比對作為唯一驗證。
- 不直接將使用者提供的 HTML 注入 DOM。
- 不執行外部嵌入程式碼內的任意 script。
- iframe 權限應遵循最小必要原則，並以實際相容性測試確認。
- 本機教材不自動上傳。
- 不預設蒐集使用者分析資料。
- 不永久保存學生名單、網址紀錄及教材內容。
- 不在前端存放任何秘密金鑰。

### 17.2 GitHub Pages

須驗證：

- Vite base 路徑。
- repository 子路徑部署。
- 靜態資源引用。
- PDF.js worker 載入路徑。
- 正式 production build。
- 重新整理及網站入口行為。
- 外部 iframe 在正式部署環境的相容性。

不得僅驗證 localhost 即宣稱正式部署可用。

## 19. 必須納入的整體驗收情境

### 情境 A：多份 PDF 課程

1. 加入 PDF A 與 PDF B。
2. PDF A 播放至第 8 頁。
3. 切換 PDF B 至第 3 頁。
4. 開啟計時器並開始倒數。
5. 返回 PDF A。

預期：PDF A 回到第 8 頁，計時器不中斷。

### 情境 B：混合來源課程

1. 加入 PDF、PowerPoint 與 Canva。
2. 依序切換教材。
3. 開啟工具列。
4. 使用抽籤及 QR Code。
5. 關閉工具並返回原教材。

預期：教材來源與控制能力正確，工具狀態保留，不出現虛假的翻頁功能。

### 情境 C：全螢幕小組討論

1. 播放教材。
2. 進入展示模式。
3. 開啟五分鐘倒數。
4. 將計時器縮成迷你浮窗。
5. 收合工具列。
6. 繼續翻頁。

預期：計時器持續執行，教材最大化且可正常操作。

### 情境 D：抽籤公平性

1. 設定 1 至 15 號。
2. 排除 3 號及 7 號。
3. 啟用不重複抽取。
4. 持續抽取至候選池耗盡。

預期：排除號碼不會出現，所有合法候選號碼各出現一次，耗盡後不可繼續抽出無效結果。

### 情境 E：QR Code 展示

1. 貼上合法網址。
2. 產生 QR Code。
3. 開啟大型展示。
4. 使用手機掃描。
5. 關閉展示。

預期：掃描內容與輸入網址一致，返回教材後原播放狀態不變。

### 情境 F：iPad 操作

1. 載入 PDF。
2. 使用觸控翻頁。
3. 展開工具列。
4. 拖曳迷你計時器。
5. 旋轉裝置。
6. 進入可用的展示模式。

預期：教材比例、浮窗位置及觸控操作均正常。

### 情境 G：外部播放器錯誤

1. 加入不允許嵌入的網址。
2. 加入需額外登入或權限的教材。
3. 模擬網路中斷。
4. 返回本機 PDF。

預期：外部播放器失敗不會造成整個工作台無法使用，本機 PDF 及課堂工具仍可正常操作。
